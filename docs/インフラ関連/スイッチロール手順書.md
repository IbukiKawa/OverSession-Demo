## 1. 事前準備

作業を開始する前に、以下が揃っていることを確認してください。

- [ ] 管理者からIAMユーザー情報（CSVファイル）を受け取っていること
  - CSVにはコンソールログインURL・ユーザー名・初期パスワードが記載されています
- [ ] スマートフォンに **Google Authenticator** がインストールされていること
  - [App Store（iOS）](https://apps.apple.com/jp/app/google-authenticator/id388497605)
  - [Google Play（Android）](https://play.google.com/store/apps/details?id=com.google.android.apps.authenticator2)

## 2. 初回ログイン

1. 管理者から受け取ったCSVに記載されている **コンソールログインURL** にアクセスする

   ```
   例: https://202516976897.signin.aws.amazon.com/console
   ```


2. CSVに記載されている **ユーザー名** と **初期パスワード** を入力してサインインする


3. ログイン成功後、**パスワードの変更画面** が表示されるので任意のパスワードに変更する

   | 項目 | 要件 |
   |------|------|
   | 最小文字数 | 8文字以上 |
   | 推奨 | 大文字・小文字・数字・記号を含む |


4. パスワード変更後、AWSマネジメントコンソールのトップ画面が表示されたらログイン完了

## 3. アクセスキーの発行

> ⚠️ アクセスキーは発行後に一度しか表示されません。必ずCSVをダウンロードして安全な場所に保管してください。

1. 画面左上の **検索欄** に `IAM` と入力し、IAMサービスを開く


2. 左メニューの **「ユーザー」** タブをクリックする


3. 一覧から **自分のユーザー名** を選択する


4. **「セキュリティ認証情報」** タブをクリックする


5. ページをスクロールして **「アクセスキー」** の欄まで移動し、**「アクセスキーを作成」** ボタンを押下する


6. ユースケースの選択画面で **「コマンドラインインターフェイス（CLI）」** を選択し、次へ進む

7. 説明タグは任意で入力し、**「アクセスキーを作成」** ボタンを押下する

8. 表示された画面で **「.csvファイルをダウンロード」** ボタンを押下して、CSVを安全な場所に保存する


   > ⚠️ この画面を閉じるとシークレットアクセスキーは二度と表示されません。必ずダウンロードしてから閉じてください。

9. **「完了」** ボタンを押下して閉じる

> 💡 AWS CLIのセットアップ（`aws configure` 等）やSTSによる一時認証情報の取得については、別途「CLI設定手順書」を参照してください。

## 4. MFA認証の有効化

AWS公式ドキュメントの手順に従って設定します。

📖 [仮想 MFA デバイスの有効化（IAMユーザー向け） - AWS公式ドキュメント](https://docs.aws.amazon.com/ja_jp/IAM/latest/UserGuide/id_credentials_mfa_enable_virtual.html#enable-virt-mfa-for-iam-user)

上記ドキュメントの手順を進める際、以下の点に注意してください。

- MFAデバイスの種類は **「仮想デバイス（Authenticator app）」** を選択する
- QRコードの読み取りには事前準備でインストールした **Google Authenticator** を使用する
- 連続する2つの認証コードの入力が求められるので、30秒待って2回目のコードが生成されてから入力する

## 5. スイッチロールの実行

アクセスキーの発行とMFAの有効化が完了したら、一度ログアウトして再ログインします。

### 5-1. 再ログインとMFA確認

1. 右上のアカウント名をクリックし、**「サインアウト」** を押下する
2. 再度ログインURLにアクセスし、ユーザー名とパスワードを入力する
3. **MFA認証コードの入力画面** が表示されたら成功 → Google Authenticatorに表示されている6桁のコードを入力する


### 5-2. スイッチロール

1. ログイン後、コンソール画面右上の **ユーザー名** をクリックする


2. ドロップダウンの一番下にある **「ロールの切り替え」** を押下する


3. スイッチロール画面に以下を入力して **「ロールの切り替え」** ボタンを押下する

   | 入力項目 | 値 |
   |---------|-----|
   | アカウント ID | `202516976897` |
   | IAM ロール名 | `myapp-dev-role` |
   | 表示名（任意） | `myapp dev` |


4. 右上の表示が **ロール名（myapp dev）** に変わっていたらスイッチロール完了


   AWSリソースを操作できるようになります。

### 5-3. 元のユーザーに戻る

1. 右上のロール名をクリックする
2. **「myapp-devに戻る」** をクリックする

> 💡 スイッチロールのセッションは **1時間** で切れます。切れた場合は5-2の手順を再度実行してください。

## 6. この構成について

### なぜIAMユーザーに直接権限を付与しないのか

本環境では以下の構成を採用しています。

```
IAMユーザー（権限なし）
  └─ myapp-dev-group
       └─ sts:AssumeRole のみ許可
                ↓ スイッチロール
          myapp-dev-role
               └─ PowerUserAccess
```

直接権限を付与しない理由は以下のとおりです。

| 理由 | 説明 |
|------|------|
| **キー漏洩時のリスク低減** | アクセスキーが漏洩しても、単体では何も操作できない |
| **権限管理の一元化** | ロール側の権限を変更するだけで全ユーザーに反映される |
| **監査ログの明確化** | CloudTrailに「誰がどのロールにスイッチしたか」が記録される |
| **最小権限の原則** | ユーザーは必要なときだけロールにスイッチして権限を取得する |
