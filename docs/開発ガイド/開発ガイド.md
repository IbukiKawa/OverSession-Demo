# ローカル開発環境 - Docker Compose ガイド

## 概要

docker-compose は**ローカル開発専用**のツール。複数のコンテナ（フロント・バック・DB等）を1コマンドでまとめて起動・停止できる。

本番環境では使わない。本番は ECS (Fargate) + Terraform + GitHub Actions でデプロイする。

```
ローカル開発:  docker-compose.yml → フロント + バック + DB をまとめて起動
本番（AWS）:   ECS (Fargate) + RDS Aurora + DynamoDB（マネージドサービス）
```

Dockerfile はローカルでも本番でも共通で使う。「どこで動かすか」が変わるだけ。

---

## docker-compose.yml の構成

```yaml
services:
  backend:         # Spring Boot アプリ
  frontend:        # Next.js アプリ
  db:              # PostgreSQL（Aurora の代替）
  dynamodb-local:  # DynamoDB Local（DynamoDB の代替）
  dynamodb-admin:  # DynamoDB の GUI 管理ツール

volumes:
  db-data:         # PostgreSQL のデータ永続化
  dynamodb-data:   # DynamoDB のデータ永続化
```

## 各サービスの解説

### backend（Spring Boot）

```yaml
backend:
  build:
    context: ./backend          # backend/ フォルダの Dockerfile を使ってビルド
    dockerfile: Dockerfile
  ports:
    - "8080:8080"               # ローカルの8080 → コンテナの8080 に転送
  environment:
    - SPRING_PROFILES_ACTIVE=local
    - DATABASE_URL=postgresql://postgres:password@db:5432/mydb
    - DYNAMODB_ENDPOINT=http://dynamodb-local:8000
    - AWS_REGION=ap-northeast-1
    - AWS_ACCESS_KEY_ID=dummy
    - AWS_SECRET_ACCESS_KEY=dummy
  depends_on:
    - db
    - dynamodb-local
```

**ポイント:**
- `DATABASE_URL` のホストが `db` になっている → docker-compose 内ではサービス名で通信できる
- `DYNAMODB_ENDPOINT` でローカルの DynamoDB Local を指定
- `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` はダミー値でOK（DynamoDB Local は認証を検証しない）
- `depends_on` で DB と DynamoDB Local が先に起動するよう順序制御

### frontend（Next.js）

```yaml
frontend:
  build:
    context: ./frontend
    dockerfile: Dockerfile
  ports:
    - "3000:3000"               # http://localhost:3000 でアクセス
  environment:
    - NEXT_PUBLIC_API_URL=http://backend:8080
  depends_on:
    - backend
```

**ポイント:**
- `NEXT_PUBLIC_API_URL` でバックエンドの接続先を指定
- `NEXT_PUBLIC_` プレフィックスはNext.jsの規約（クライアント側で参照可能にするため）

### db（PostgreSQL）

```yaml
db:
  image: postgres:16-alpine     # 公式イメージをそのまま使う（ビルド不要）
  ports:
    - "5432:5432"
  environment:
    - POSTGRES_USER=postgres
    - POSTGRES_PASSWORD=password
    - POSTGRES_DB=mydb
  volumes:
    - db-data:/var/lib/postgresql/data   # データ永続化
  healthcheck:
    test: ["CMD-SHELL", "pg_isready -U postgres"]
    interval: 5s
    timeout: 5s
    retries: 5
```

**ポイント:**
- `image` を直接指定 → Dockerfile不要。公式イメージをそのまま使う
- `volumes` でデータを永続化。これがないと `docker compose down` でデータが消える
- `healthcheck` で DB が本当に接続可能になったか確認。backend の `depends_on: condition: service_healthy` と組み合わせて使う

### dynamodb-local

```yaml
dynamodb-local:
  image: amazon/dynamodb-local  # AWS公式のローカルエミュレーター
  ports:
    - "8000:8000"
  command: "-jar DynamoDBLocal.jar -sharedDb"
  volumes:
    - dynamodb-data:/home/dynamodblocal/data
```

**ポイント:**
- AWS が公式に提供している DynamoDB のローカル版
- 本物の DynamoDB とほぼ同じ API で動作する
- インターネット接続不要、課金なし
- `-sharedDb` オプション: 全リクエストが同じDBファイルを共有する（これがないとアクセスキーごとに別DBになる）

**ローカルと本番の違い:**

| 項目 | ローカル（DynamoDB Local） | 本番（DynamoDB） |
|------|--------------------------|-----------------|
| 認証 | なし（ダミーでOK） | IAMロール |
| 接続先 | http://localhost:8000 | AWSが自動解決 |
| 料金 | 無料 | 従量課金 |
| データ永続性 | volumes で永続化 | AWS が管理 |

**アプリ側での接続分岐:**
```java
// 環境変数 DYNAMODB_ENDPOINT が設定されていればローカル接続
// 設定されていなければ本番（AWS）に自動接続
```

### dynamodb-admin（GUI管理ツール）

```yaml
dynamodb-admin:
  image: aaronshaf/dynamodb-admin
  ports:
    - "8001:8001"
  environment:
    - DYNAMO_ENDPOINT=http://dynamodb-local:8000
    - AWS_REGION=ap-northeast-1
    - AWS_ACCESS_KEY_ID=dummy
    - AWS_SECRET_ACCESS_KEY=dummy
  depends_on:
    - dynamodb-local
```

**ポイント:**
- http://localhost:8001 でブラウザからテーブルやデータを確認・編集できる
- PostgreSQL における A5:SQL のようなもの
- 必須ではないが、開発時のデータ確認に便利

## 基本コマンド

```bash
# 全サービスをビルド＆起動
docker compose up --build

# バックグラウンドで起動
docker compose up -d

# ログをリアルタイム確認
docker compose logs -f

# 特定サービスのログだけ見る
docker compose logs -f backend

# 全サービス停止
docker compose down

# 全サービス停止 + データも削除
docker compose down -v

# 特定サービスだけ再ビルド＆再起動
docker compose up --build backend
```

## コンテナ間の通信

docker-compose 内のコンテナは**サービス名**で互いに通信できる。localhost ではない。

```
frontend → backend:8080     （サービス名で接続）
backend  → db:5432          （サービス名で接続）
backend  → dynamodb-local:8000（サービス名で接続）
```

ブラウザからアクセスする場合は `localhost` を使う:
```
ブラウザ → localhost:3000   （frontend）
ブラウザ → localhost:8080   （backend）
ブラウザ → localhost:8001   （dynamodb-admin）
```

---

## volumes（データ永続化）

```yaml
volumes:
  db-data:          # PostgreSQL のデータ
  dynamodb-data:    # DynamoDB のデータ
```

- `docker compose down` → コンテナは消えるがデータは残る
- `docker compose down -v` → データも含めて全削除（クリーンスタートしたいとき）

## TODO: 今後の改善ポイント

### 1. 環境変数の .env ファイルへのリファクタ

現状は docker-compose.yml に直接書いているが、.env ファイルに切り出すべき。

**現状（docker-compose.yml に直書き）:**
```yaml
environment:
  - POSTGRES_USER=postgres
  - POSTGRES_PASSWORD=password
  - DATABASE_URL=postgresql://postgres:password@db:5432/mydb
```

**改善後（.env ファイルに分離）:**

`.env`:
```
POSTGRES_USER=postgres
POSTGRES_PASSWORD=password
POSTGRES_DB=mydb
DATABASE_URL=postgresql://postgres:password@db:5432/mydb
DYNAMODB_ENDPOINT=http://dynamodb-local:8000
AWS_REGION=ap-northeast-1
AWS_ACCESS_KEY_ID=dummy
AWS_SECRET_ACCESS_KEY=dummy
```

`docker-compose.yml`:
```yaml
backend:
  env_file:
    - .env
```

**メリット:**
- パスワード等の秘匿情報が docker-compose.yml から分離される
- `.env` を `.gitignore` に追加すれば Git に秘匿情報がコミットされない
- `.env.example` をリポジトリに置いて、必要な環境変数の一覧を共有できる
- 環境ごと（local / staging / production）に .env ファイルを切り替えやすい

### 2. healthcheck の追加

DynamoDB Local にも healthcheck を追加して、確実に起動完了してから backend が接続するようにする。

```yaml
dynamodb-local:
  healthcheck:
    test: ["CMD-SHELL", "curl -s http://localhost:8000/shell/ || exit 1"]
    interval: 5s
    timeout: 5s
    retries: 5

backend:
  depends_on:
    db:
      condition: service_healthy
    dynamodb-local:
      condition: service_healthy
```

### 3. Makefile の導入

よく使うコマンドを Makefile にまとめると、チームメンバーが覚えるコマンドが減る。

```makefile
.PHONY: up down logs build

up:
	docker compose up -d

down:
	docker compose down

logs:
	docker compose logs -f

build:
	docker compose up --build -d

clean:
	docker compose down -v
```

使い方:
```bash
make up      # 起動
make down    # 停止
make logs    # ログ確認
make clean   # データも含めて全削除
```

### 4. GitHub Actions での CI/CD

```
push → GitHub Actions → docker build → ECR プッシュ → ECS デプロイ
```

ローカルで動作確認した Dockerfile をそのまま本番にデプロイする流れを自動化する。
